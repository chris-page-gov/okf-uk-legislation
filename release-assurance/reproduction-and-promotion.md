# Release-candidate reproduction and promotion

The fail-closed [release policy v2](release-policy.json) separates evidence
into two planes:

- **embedded evidence** is generated before freeze and committed with the
  candidate; and
- **external write-once evidence** is generated from or against the exact
  frozen commit without changing that commit or rebuilding its archive.

The embedded
[`release-report.json`](../bundle/release-assurance/release-report.json) closes
GATE-12 only when it records relationship composition, coverage and snapshot
currency, unresolved gaps, licence/access escalations, executed evaluation,
model cost and the YAML-LD MIME exception. Its passing status is a reporting
claim, not a claim that any post-freeze gate has run.

The machine-readable
[external finalization contract](external-finalization-contract.json), its
[pre-RC authorization schema](schemas/pre-rc-authorization-receipt.schema.json),
[final-promotion authorization schema](schemas/final-promotion-authorization-receipt.schema.json)
and [final receipt schema](schemas/external-finalization-receipt.schema.json)
control the external plane. The offline
[finalizer](../scripts/finalize_release_candidate.py) reconstructs every
receipt from local evidence and performs no publication or network access.
RC and final release identity and asset metadata are separately bound by the
[GitHub release-observation schema](schemas/github-release-observation.schema.json).
The clean-room provenance also freezes
[`capture_github_release_observation.py`](../scripts/capture_github_release_observation.py).
The offline finalizer rejects an observation unless its immutable attempt
manifest records that exact controller SHA-256; copying the JSON from another
tool or candidate therefore cannot satisfy the release gate.

## One archive, two releases

GATE-06 creates one deterministic release archive from the exact frozen
candidate commit:

```text
okf-uk-legislation-v0.3.0.tar.zst
```

The filename intentionally names the production version, not the release
candidate tag. The same literal filename is attached first to
`v0.3.0-rc.1` and then to `v0.3.0`.

Promotion means reusing the exact regular file and verifying its recorded
SHA-256 before and after upload. It does not mean running the builder again,
recompressing the tar stream, changing metadata inside the archive or renaming
the asset. If the hosting service requires a separate upload for the final
release, that upload must read the already sealed RC archive; the RC asset
remains available and both downloaded files must have the same byte count and
SHA-256.

The [reproduction profile](reproduction-profile.json) controls archive
construction. A successful `release-package-manifest.json`, validated by the
[release-package manifest schema](schemas/release-package-manifest.schema.json),
binds the candidate commit, publication inventory, semantic digests, archive
filename, archive digest and both release tags. Any mismatch creates a new
candidate and requires the gated validation sequence to run again.

The profile rebuilds the complete base publication first with
`build_legislation_okf.py --from-existing`. That offline mode reads the
checked-in corpus shards and preserves the frozen descriptor timestamp, so it
tests the base publication rather than relying on already generated bytes.
Extension and assurance projections follow. Checksums are generated once
before release assurance to provide its integrity input, and once after it so
the final inventory also binds the assurance files. Both checksum passes are
part of the controlled build sequence.

## External evidence directory

All arguments which contain post-freeze evidence and every output receipt must
resolve outside the frozen repository. Use regular, non-symbolic-link files in
a durable directory such as `/srv/okf-release-evidence/v0.3.0/`; `/tmp` below
is illustrative only. Keep the reproduction package, Explorer receipt,
security receipt, accessibility receipt, performance receipt, deployed-route
attempt, traceability-closure receipt, write-once GitHub release observations
and downloaded release assets unchanged.

The finalizer creates a missing receipt atomically. Repeating an authorizing
command with byte-identical evidence is idempotent. It refuses to replace an
existing receipt with different bytes. Verification commands never write.

The examples below use these external paths:

```text
/tmp/okf-v0.3.0/reproduction/
/tmp/okf-v0.3.0/explorer-release-receipt.json
/tmp/okf-v0.3.0/security-assurance-receipt.json
/tmp/okf-v0.3.0/accessibility-assurance-receipt.json
/tmp/okf-v0.3.0/performance-assurance-receipt.json
```

## 1. Authorize and verify the RC

After the exact commit is frozen, run clean-room reproduction and the required
Explorer, security, accessibility and performance checks against it. Then
write the pre-RC receipt:

```sh
.venv/bin/python scripts/finalize_release_candidate.py authorize-rc \
  --reproduction-dir /tmp/okf-v0.3.0/reproduction \
  --explorer-receipt /tmp/okf-v0.3.0/explorer-release-receipt.json \
  --security-receipt /tmp/okf-v0.3.0/security-assurance-receipt.json \
  --accessibility-receipt /tmp/okf-v0.3.0/accessibility-assurance-receipt.json \
  --performance-receipt /tmp/okf-v0.3.0/performance-assurance-receipt.json \
  --receipt /tmp/okf-v0.3.0/pre-rc-authorization-receipt.json
```

Reconstruct it independently before publishing:

```sh
.venv/bin/python scripts/finalize_release_candidate.py verify-rc \
  --reproduction-dir /tmp/okf-v0.3.0/reproduction \
  --explorer-receipt /tmp/okf-v0.3.0/explorer-release-receipt.json \
  --security-receipt /tmp/okf-v0.3.0/security-assurance-receipt.json \
  --accessibility-receipt /tmp/okf-v0.3.0/accessibility-assurance-receipt.json \
  --performance-receipt /tmp/okf-v0.3.0/performance-assurance-receipt.json \
  --receipt /tmp/okf-v0.3.0/pre-rc-authorization-receipt.json
```

Only after `verify-rc` passes may the sealed archive be attached, unchanged, to
the immutable `v0.3.0-rc.1` release.

## 2. Authorize final promotion

Download the published RC asset to a regular external file and run the
write-once deployed-entrypoint attempt against the RC. Close the frozen
traceability ledger with a separate GATE-14 receipt. The public attempt must
bind the frozen commit, bundle inventory, Explorer `v0.5.0`, RC tag and exact
archive URL.

Authorize promotion before a final release asset exists:

```sh
.venv/bin/python scripts/finalize_release_candidate.py authorize-final-promotion \
  --reproduction-dir /tmp/okf-v0.3.0/reproduction \
  --explorer-receipt /tmp/okf-v0.3.0/explorer-release-receipt.json \
  --security-receipt /tmp/okf-v0.3.0/security-assurance-receipt.json \
  --accessibility-receipt /tmp/okf-v0.3.0/accessibility-assurance-receipt.json \
  --performance-receipt /tmp/okf-v0.3.0/performance-assurance-receipt.json \
  --pre-rc-authorization /tmp/okf-v0.3.0/pre-rc-authorization-receipt.json \
  --public-attempt /tmp/okf-v0.3.0/public-attempt \
  --traceability-receipt /tmp/okf-v0.3.0/traceability-closure-receipt.json \
  --rc-release-observation /tmp/okf-v0.3.0/okf-uk-legislation-v0.3.0-rc.1-release-observation.json \
  --rc-asset /tmp/okf-v0.3.0/rc/okf-uk-legislation-v0.3.0.tar.zst \
  --rc-release-url https://github.com/chris-page-gov/okf-uk-legislation/releases/download/v0.3.0-rc.1/okf-uk-legislation-v0.3.0.tar.zst \
  --receipt /tmp/okf-v0.3.0/final-promotion-authorization-receipt.json
```

This receipt proves that the public RC is eligible for promotion. It neither
creates nor predicts a final asset. Only after this command passes may the
same sealed regular file be uploaded under `v0.3.0`, with the same literal
filename.

## 3. Finalize and verify the published release

Download the final asset independently. `finalize` requires both downloaded
assets and the prior final-promotion authorization, and rehashes all three
copies: the sealed package archive, the RC download and the final download.

```sh
.venv/bin/python scripts/finalize_release_candidate.py finalize \
  --reproduction-dir /tmp/okf-v0.3.0/reproduction \
  --explorer-receipt /tmp/okf-v0.3.0/explorer-release-receipt.json \
  --security-receipt /tmp/okf-v0.3.0/security-assurance-receipt.json \
  --accessibility-receipt /tmp/okf-v0.3.0/accessibility-assurance-receipt.json \
  --performance-receipt /tmp/okf-v0.3.0/performance-assurance-receipt.json \
  --pre-rc-authorization /tmp/okf-v0.3.0/pre-rc-authorization-receipt.json \
  --public-attempt /tmp/okf-v0.3.0/public-attempt \
  --traceability-receipt /tmp/okf-v0.3.0/traceability-closure-receipt.json \
  --rc-release-observation /tmp/okf-v0.3.0/okf-uk-legislation-v0.3.0-rc.1-release-observation.json \
  --rc-asset /tmp/okf-v0.3.0/rc/okf-uk-legislation-v0.3.0.tar.zst \
  --final-promotion-authorization /tmp/okf-v0.3.0/final-promotion-authorization-receipt.json \
  --final-release-observation /tmp/okf-v0.3.0/okf-uk-legislation-v0.3.0-release-observation.json \
  --final-asset /tmp/okf-v0.3.0/final/okf-uk-legislation-v0.3.0.tar.zst \
  --rc-release-url https://github.com/chris-page-gov/okf-uk-legislation/releases/download/v0.3.0-rc.1/okf-uk-legislation-v0.3.0.tar.zst \
  --final-release-url https://github.com/chris-page-gov/okf-uk-legislation/releases/download/v0.3.0/okf-uk-legislation-v0.3.0.tar.zst \
  --receipt /tmp/okf-v0.3.0/external-finalization-receipt.json
```

Finally reconstruct the final receipt from the unchanged evidence:

```sh
.venv/bin/python scripts/finalize_release_candidate.py verify-final \
  --reproduction-dir /tmp/okf-v0.3.0/reproduction \
  --explorer-receipt /tmp/okf-v0.3.0/explorer-release-receipt.json \
  --security-receipt /tmp/okf-v0.3.0/security-assurance-receipt.json \
  --accessibility-receipt /tmp/okf-v0.3.0/accessibility-assurance-receipt.json \
  --performance-receipt /tmp/okf-v0.3.0/performance-assurance-receipt.json \
  --pre-rc-authorization /tmp/okf-v0.3.0/pre-rc-authorization-receipt.json \
  --public-attempt /tmp/okf-v0.3.0/public-attempt \
  --traceability-receipt /tmp/okf-v0.3.0/traceability-closure-receipt.json \
  --rc-release-observation /tmp/okf-v0.3.0/okf-uk-legislation-v0.3.0-rc.1-release-observation.json \
  --rc-asset /tmp/okf-v0.3.0/rc/okf-uk-legislation-v0.3.0.tar.zst \
  --final-promotion-authorization /tmp/okf-v0.3.0/final-promotion-authorization-receipt.json \
  --final-release-observation /tmp/okf-v0.3.0/okf-uk-legislation-v0.3.0-release-observation.json \
  --final-asset /tmp/okf-v0.3.0/final/okf-uk-legislation-v0.3.0.tar.zst \
  --rc-release-url https://github.com/chris-page-gov/okf-uk-legislation/releases/download/v0.3.0-rc.1/okf-uk-legislation-v0.3.0.tar.zst \
  --final-release-url https://github.com/chris-page-gov/okf-uk-legislation/releases/download/v0.3.0/okf-uk-legislation-v0.3.0.tar.zst \
  --receipt /tmp/okf-v0.3.0/external-finalization-receipt.json
```

`verify-final` is the terminal check. It proves that the write-once external
chain closes GATE-06 through GATE-10 and GATE-13 through GATE-14 for the exact
frozen commit and identical archive bytes. It does not amend the embedded
candidate or copy external evidence back into the repository.

The public route test uses the same literal filename beneath the active release
tag. See the [public entry-point smoke procedure](public-entrypoint-smoke.md).
