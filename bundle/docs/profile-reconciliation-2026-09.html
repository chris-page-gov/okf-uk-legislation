Profile reconciliation history (September 2026)

Historical and superseded. Release v0.4.0 adopted the reconciled profile, bounded navigation, repaired validation and current Explorer contract on 3 November 2026. The observations below record the candidate state at the time they were made. They are retained as evidence and must not be read as the current publication or release status.

This was an independent experimental candidate for technical review, separate from the September DWP reading-help demonstration. References below to an unchanged v0.3.0 release, failed gates or work not being merge-ready describe that historical checkpoint only.

What changed

An OKF profile defines the common shapes that a bundle and its consumer understand. This candidate vendors the exact canonical profile and records its file hashes. Legislation-specific structures have separate versioned schema identifiers rather than reusing the common identifier for a different shape.

The candidate projects the legislation descriptors into the supported shapes. It retains an explicit extension for additional legislation metadata. Child links preserve a local or commit-pinned source instead of silently switching to public main. The source laws and historical assertion evidence are retained.

Large relationship routes keep their existing limits. The bounded graph alternatives offer smaller work-specific routes. These examples do not represent every relationship in the larger route. Correction notices are identified separately from newly published legal works.

The original unfinished migration remains in its original checkout. A hash-inventoried copy was preserved before selectively reconciling authored changes with remote main 93e072f0010af26c383381c0c59ea1ed66ff381a.

  • Explorer's bound runtime gate currently requires v0.6.2. The current implementation reports package 0.7.0, and the existing v0.7.0 tag refers to an earlier commit. Neither tag may be moved to manufacture a passing gate.
